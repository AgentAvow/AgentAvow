# 0006: The OpenAPI document is committed, and CI fails on breaking changes

- **Status:** Accepted
- **Date:** 2026-11-16
- **Decided by:** the owner (issue #408, triage of #402's wishlist)

## Context

The MCP server, the Claude Code plugin, the GitHub Action, the GitLab and other CI
templates, the SDKs and third-party verifiers all call the REST API. Nothing stopped a
route or model change from breaking them: the OpenAPI document was generated at
runtime (`/api/v1/openapi.json`) and never compared with anything.

Most routes live under `/api/v1`, but some can't move: protocol-fixed paths
(`/.well-known/*`, the Bluesky `/xrpc/*` feed routes), the unversioned health probes the
deploy script and monitors read, and the `/mcp` connector, which is a mounted ASGI app
and has no OpenAPI description at all.

## Decision

1. **Committed document.** `docs/api/openapi.json` is generated by
   `scripts/openapi/generate.py` (`make openapi`). The app is imported in a child
   process with a fixed environment and an empty working directory, so shell variables
   or an untracked `.env` cannot change which routes are registered. Output is JSON
   with sorted keys, two-space indent and a trailing newline. The text also depends on
   the FastAPI and pydantic versions (the repo has no lock file, and the first CI run
   already differed from a local venv), so `docs/api/openapi-toolchain.txt` pins
   fastapi, pydantic, pydantic-core and starlette. The generator refuses other versions.
   `make openapi-venv` builds `.venv-openapi` with the pins, and the CI job installs
   with them as constraints. Bumping the pins is its own PR, with the regenerated file.
2. **Staleness gate.** `generate.py --check` (CI job `api-contract`, and
   `tests/test_openapi_contract.py` in the backend suite) fails when the committed
   file differs from the code, and says to run `make openapi`.
3. **Breaking-change gate.** On every PR, `scripts/openapi/breaking.py` compares the
   PR's document with the base branch's. It fails on a removed operation; a removed
   parameter, a new required parameter or one made required; a request body made
   required; a removed request property, a new required request property, a narrowed
   request type or a removed request enum value; a removed response status or media
   type; a removed response property, one no longer always present, or a changed or
   widened response type (newly nullable counts). Additions pass. It is a small
   in-repo checker (`tests/test_openapi_breaking.py` pins each rule and plants breaks
   in the real document), chosen over `oasdiff` so the rules are readable here and CI
   needs no extra binary.
4. **Approved breaks.** When the owner approves a break, each line the gate printed
   goes into `docs/api/approved-breaks.json` with a reason (`*` matches any run of
   characters). The file is reviewed in the PR like code. Entries that stop matching
   (because the base branch now has the change) are reported as safe to delete.
5. **Routes are versioned.** Every route sits under `/api/v<N>` unless
   `docs/api/route-allowlist.json` lists it under `outside_version_prefix` with a
   reason. Every `/api/v<N>` route hidden from the document (`include_in_schema=False`,
   WebSockets) is listed under `not_in_openapi` with a reason, because the gate cannot
   see it. The tests fail on an unlisted route and on a listed route that no longer
   exists.
6. **`/mcp` is not covered by this diff.** It is not in the OpenAPI document. Its tool
   list stays pinned by the existing guards: `tests/fixtures/mcp_tools_list_snapshot.json`,
   `tests/fixtures/mcp_wire_2025_11_25/tools_list.json`, `EXPECTED_TOOLS_LIST_SHA256` in
   `src/jobs/mcp_health.py` and the digest in `tests/test_mcp_card_trust_adoption_c.py`,
   plus the owner's Rescan of the published ChatGPT app. Keep both.

## Consequences

- A route or model change has to come with a regenerated `docs/api/openapi.json`; the
  diff shows reviewers exactly what clients will see.
- Removing or renaming a field means keeping the old one beside the new one, or an
  approved-breaks entry the owner signs off in review.
- The gate checks structure, not meaning: a field that keeps its name and type but
  changes what it means passes. Error bodies (ADR 0005) are checked only as far as
  each route documents them.
- Routes hidden from the document (the plugin's `/public/plugin/active` ping, HTML
  pages, badge HEAD) are not checked by the diff. Their own tests guard them.
- The document describes the code under the pinned FastAPI and pydantic. Prod installs
  whatever the version ranges allow, so its live `/api/v1/openapi.json` can differ in
  small ways (a regex `pattern`, say). Bump the pins from time to time. The breaking
  gate shows whether a bump changes anything clients rely on.
- In the backend test job (unpinned versions) the staleness tests skip with a message.
  The `api-contract` job is the gate.
- The very first PR has no base document, so its breaking step reports "nothing to
  compare" and passes.

## Evidence
